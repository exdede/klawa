# Phase 0 — Build Pipeline + Throwaway Keyboard Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove the whole Linux → GitHub Actions → SideStore → iPhone path works with a throwaway keyboard, before any real keyboard code.

**Architecture:** XcodeGen spec generates the Xcode project on a GitHub macOS runner. The runner builds unsigned, embeds entitlements with `ldid`, zips an `.ipa` and uploads it to a fixed release URL. SideStore on the phone signs and installs it.

**Tech Stack:** Swift 5, UIKit (keyboard), SwiftUI (app), XcodeGen, GitHub Actions `macos-latest`, ldid, SideStore, iloader.

**Spec:** `docs/superpowers/specs/2026-11-24-iphone-keyboard-design.md` (Phase 0).

## Global Constraints

- Deployment target iOS 17.0; device is iOS 27.2.1.
- Exactly 2 targets: app `com.exdede.klawa`, keyboard extension `com.exdede.klawa.keyboard` (free Apple ID = 10 App IDs / week).
- App Group `group.com.exdede.klawa`; at runtime prefer the SideStore-rewritten group from Info.plist key `ALTAppGroups`, fall back to the hardcoded ID.
- Keyboard Info.plist: `RequestsOpenAccess = true`, `PrimaryLanguage = pl-PL`.
- Public repo `exdede/klawa`. Fixed download URL: `https://github.com/exdede/klawa/releases/download/nightly/Klawa.ipa`.
- Nothing typed is logged or sent anywhere.

## Review Focus

1. SideStore reads entitlements from the signed binary: unsigned build without `ldid` loses the App Group silently. CI must `ldid -S` both binaries.
2. SideStore renames the App Group: hardcoded group ID would read an empty container. Resolution must check `ALTAppGroups` first.
3. Keyboard without Full Access: `UserDefaults(suiteName:)` write fails silently; app must show "no data" instead of crashing.
4. Globe key: on Face ID iPhones iOS draws it below; keyboard must still add its own when `needsInputModeSwitchKey` is true.
5. CI run on a repo with no `nightly` release yet: workflow must create it, not fail.
